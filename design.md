# PitMind — Design

## Decisions & Defaults

| Decision | Choice | Notes |
|---|---|---|
| Simulator | ACC (PC) | Shared memory via `pyaccsharedmemory` |
| MVP scope | Offline CSV analysis | Live telemetry (v0.6) later |
| Tracks | All F1 circuits | Track-agnostic detection; no per-track config at analysis time |
| Data acquisition | Own recorder → CSV | Avoid fragile MoTeC `.ld` export |
| Dev/test data | Synthetic generator on **real F1 circuit geometry** | bacinger/f1-circuits (MIT/OSM); Monza default, Spa/Silverstone/… also vendored |
| Synthetic physics | Discrete-corner kinematic model | Corner regions auto-derived from the circuit's curvature; per-corner mistakes injected with labels |
| Reference lap | Best lap (+ best corner, best sector for potential lap) | Configurable |
| Mistake detection | Threshold rules (doc §14) | Thresholds in config; ML later (doc §26) |
| Time loss | Kinematic heuristic | ML later once labeled data exists |
| Coaching | Templates | Optional LLM hook isolated (doc §21) |
| UI | Streamlit + Plotly | Quick MVP dashboards |

## Synthetic Track Data (fixtures only)

Dev/test telemetry is generated by driving around **real F1 circuit geometry** so the pipeline is
exercised on realistic layouts (Monza's chicanes, Spa's Eau Rouge, Silverstone's Maggotts–Becketts…).

- **Source:** `bacinger/f1-circuits` GeoJSON `LineString` per circuit (closed loop of WGS84 points,
  ~1–3 km² extent, official `length` property). Vendored into `data/circuits/` with attribution
  (MIT; data derived from OpenStreetMap, ODbL).
- **Conversion** (`synthetic/circuit.py`): project lat/lon → local meters (equirectangular about the
  circuit's origin — error ≪ 0.1 % over ~6 km), then resample to a uniform ~1 m arc-length grid
  (raw GeoJSON density is coarse/uneven on straights) and lightly smooth it.
- **Corner derivation:** corner regions (start / apex / end `s`) are found on the centerline with the
  **same chord-curvature** logic `pitmind/corners.py` uses on telemetry. Each region gets a radius
  (from peak curvature) → corner speed limit `√(A_lat · R)`. Ground truth = these regions.
- **Driving** (`synthetic/generator.py`): the discrete-corner kinematic planner brakes before each
  corner to its limit, apexes, and exits on throttle — exactly the old generic model, but fed real
  geometry. Per-lap mistakes (`brake_shift_m`, `apex_deficit_kmh`, `throttle_delay_s`,
  `exit_deficit_kmh`) are still injected per corner with known labels for tests.
- **Loop closure:** the circuit polyline closes (start == finish), so the tp≈0/1 seam is continuous —
  this is why chord-based corner detection is reliable near the seam (the old generic track had an
  open loop and produced a 1.7 km seam jump).
- **Legacy:** the hand-built generic F1 test track stays as a `generic` fallback fixture with its
  seam fixed; real circuits are the default.

## CSV Telemetry Schema (the contract)

Emitter: recorder AND synthetic generator. Column names fixed.

```text
timestamp                 float     seconds since start of recording
lap_number                int       completed lap counter
sector                    int       1..3
track_position            float     0..1 around the lap (ACC normalized_car_position)
speed_kmh                 float
throttle                  0..1
brake                     0..1
steering                  float     -1..1 (ACC convention)
gear                      int
rpm                       float
x, y, z                   float     world coordinates (meters)
```

Extra columns allowed (optional) but the pipeline requires the ones above.

## Derived / Corner Dataset Schema

Produced by `events.corner_features_table` (≡ `features.py`), one row per lap per corner (doc §25):

```text
lap                          int       lap number
corner                       int       corner index
start_tp / end_tp            float     corner arc window in [0, 1)
apex_tp                      float     position of peak curvature (min radius)
brake_start_tp               float     position where braking begins
brake_point_m                distance marker (or track_position) where braking starts
entry_speed_kmh              speed at corner entry
apex_speed_kmh               min speed in the corner (slowest)
exit_speed_kmh               speed at corner exit
throttle_on_s                seconds from corner start to throttle resume (>threshold)
corner_time_s                seconds from corner start to end
steering_max                 max |steering| in corner
time_loss_s                  estimated lost seconds vs reference   (added by timeloss)
```

## Threshold Defaults (config.yaml)

```yaml
ranges:
  brake_point_delta_m:      # early/late braking severity
    siginificant: 3.0
    potential:    10.0
    strong:       15.0
  apex_speed_delta_kmh: 5.0
  throttle_delay_s: 0.1
  exit_speed_delta_kmh: 3.0
  steering_excess: 0.15

detection:
  min_brake_pressure: 0.2      # brake event >= this = event start
  throttle_resume: 0.3         # throttle above this counts as "on"
  sample_rate_hz: 60           # resample target
  corner_curv_threshold: 0.0008  # rad/m; sustained turning required (chord window)
  corner_merge_m: 40.0           # join runs closer than this (e.g. chicane teeth)
  max_brake_lookback_m: 800.0    # search window behind a corner for its braking point

timeloss:
  mode: kinematic              # heuristic until ML model exists

synthetic:
  laps: 12                     # laps per generated session
  track_kind: monza            # circuit id in data/circuits/ (or "generic")
  reference_lap_rank: 1        # which clean lap is the reference in synthetic GT
```

Thresholds are placeholders until validated against real ACC laps — never magic numbers
scattered in code.

## Coaching Style (doc §19, §38)

Bad: "You seem to have braked earlier than usual at Turn 3..."
Better: "Brake 10 meters later into Turn 3."
Best: "Carry 9 km/h more speed into Turn 3."

- Precision over conversation.
- Short, actionable, non-repetitive.
- Not every mistake triggers feedback — priority system (doc §18).

## Success Criteria (doc §35)

1. Ingest ACC telemetry (recorder + CSV).
2. Identify corners and driving events automatically.
3. Detect meaningful deviations vs reference.
4. Identify likely cause of lost time.
5. Estimate lost time per corner/lap + potential lap.
6. Generate concise coaching feedback.
7. Offline end-to-end latency acceptable (fast enough to later go real-time).
8. **The real test:** following the advice measurably improves lap time.

## MVP Acceptance (doc §29)

System can say reliably:

> **Turn 3: Brake 12m later. Estimated loss 0.18s.**

backed by a Streamlit dashboard showing the evidence (plots, corner table, mistake cards).
